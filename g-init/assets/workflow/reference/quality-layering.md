# 质量分层（当前内联流程）

## 生成期

decision-memo 保存承重约束与人的决策。生成时按 schema、TG 与项目规则成文，写后用 status 检查存在态、validate 检查其实际覆盖的结构，再全文读回核验。配置规则本身不构成硬保证。

## 实现期

每票实现后分别过 Standards 与 Spec 自审，实际运行验收命令，再提交完成标签。中断恢复只认已提交的标签；勾框不能独立证明验收完成。

## 事后检查

g-review code 从整个 change 的范围、需求覆盖、错误路径与领域约束再检查一遍；g-done verify 逐需求核验真实证据，并覆盖评审修复后的测试。两者都是主 session 的后续检查，不具备独立上下文。

## 上下文与人门

阶段交界可按入口要求清理上下文，以检查盘面材料是否自足；这不能保证消除作者偏置。阶段内部从盘面续跑。设计门仍要求人的明确批准，其余按 gate 连续执行。流程定义见 ../workflow.md，报告契约见对应 SKILL.md。
